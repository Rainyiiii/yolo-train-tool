# 本地优先协作标注

YOLO团队训练平台的协作标注中心是不依赖 Docker 的图片目标检测标注服务。每台电脑都可以独立工作，也可以临时成为局域网主机。

## 两种运行模式

### 个人模式

Windows 双击：

```text
启动个人标注中心.cmd
```

Ubuntu：

```bash
bash ubuntu_start_annotation.sh
```

服务只监听 `127.0.0.1:9000`，其他电脑无法连接。图片、账号、标注和数据库保存在安装工作区的 `Workspace/annotation-hub`。

### 局域网共享模式

Windows 双击：

```text
开启局域网协作标注.cmd
```

Ubuntu：

```bash
bash ubuntu_start_annotation.sh --share
```

主机监听 `0.0.0.0:9000`。脚本会打印伙伴访问地址，例如：

```text
http://192.168.3.1:9000/
```

伙伴只需使用同一局域网中的浏览器访问，不需要安装 Docker、Python 或客户端软件。Windows 第一次共享时可能弹出防火墙提示，只允许“专用网络”，不要开放到公网。

个人模式与共享模式使用同一个工作区，切换模式不会复制或删除数据。同一台电脑一次只能运行一个模式。

服务端口使用独占监听。即使绕过启动脚本直接重复运行服务，第二个实例也会明确报端口占用并退出，避免请求随机落到两个数据库实例。

## 第一次使用

1. 打开标注中心，首次运行时创建管理员，密码至少 8 位。
2. “项目中心”里的目标检测项目会自动出现在标注中心，不需要重复创建；新增图片也会自动补充导入。
3. 选择项目后会自动打开第一张待处理图片，选择类别并拖动画框。
4. 点击“完成并下一张”，当前图片会直接进入可训练数据集，并自动切换到下一张。

个人使用到这里就可以完成全部流程。需要多人协作时，再按需创建成员账号；成员登录后能看到同一项目，打开“未开始”图片时会自动领取，不要求管理员提前分配任务。已被领取或指定给其他成员的图片不会进入自己的队列。任务分配用于提前指定负责人，双人审核用于严格质检，两者默认都不是必经步骤。

管理员与审核员可查看全部项目和图片；标注员可查看团队项目、公共未领取图片以及已经由自己领取的图片。

## 标注与并发保护

- 打开图片时会获得五分钟编辑锁；编辑和保存会续期。
- 其他成员不能同时覆盖同一张图片。
- “仅保存”用于暂存进度，状态为“标注中”。
- 默认点击“完成并下一张”后直接标记为“已完成”，无需提交审核。
- 如果项目开启了“双人审核”，完成后才会进入“待审核”；审核员可以通过或填写原因后退回修改。
- 保存时会检查修订号；旧页面不能覆盖已经更新的标注。

当前支持图片目标检测矩形框；鼠标在画布中移动时会显示横竖虚线和实时坐标，便于对齐目标。标注框可选择、移动、四角缩放、改类别、撤销/重做和缩放视图。快捷键：`B` 画框、`V` 或 `D` 选择、`Delete` 删除、`Ctrl+Z/Y` 撤销/重做、`Ctrl+S` 保存、`Ctrl+Enter` 完成并进入下一张、方向键切换图片、`0` 适应窗口、`+/-` 缩放。多边形、实例分割、旋转框和关键点计划在后续版本增加。

## 每个人独立并按需共享

每台电脑都可以保存自己的项目。需要交换时，在项目管理中下载 `.ytp-project.zip` 项目包。项目包包含：

- 项目名称、任务类型和类别表；
- 原始图片；
- 检测框、状态、修订号和审核备注；
- 数据集版本指纹。

另一台电脑填写项目包所在路径后即可导入。项目包会保留项目的审核设置。为兼容旧项目包并避免把历史个人结果直接当作团队真值：

- 含标注的图片导入后进入“待审核”；
- 没有标注的图片进入“未分配”；
- 导入操作始终创建新项目，不覆盖已有项目。

第一版不做多台数据库的自动双向同步。离线后两个人同时修改同一图片会产生无法自动判断的冲突，因此实时团队编辑必须连接同一主机。

## 数据集导出

已完成的图片可以进入训练数据集导出；开启双人审核的项目需要审核通过。目前支持：

- Ultralytics YOLO：`data.yaml`、`images/train|val|test`、`labels/train|val|test`；
- COCO Detection：图片与 `annotations/instances_default.json`；
- Pascal VOC：`JPEGImages`、`Annotations`、`ImageSets/Main`；
- LabelMe：图片与逐图 JSON；
- YOLO团队训练平台项目包：用于个人与团队工作区交换。

YOLO 和 VOC 会按图片相对路径进行稳定的 80%/10%/10% 划分。同一个版本重复导出时，图片不会随机换组。

## 数据与备份

“项目与团队”顶部固定显示当前项目来源、图片数量和完成进度；项目与图片、当前流程、团队成员与任务、项目包与数据集导出、危险操作按需展开，日常标注不需要滚过低频设置。管理员在“危险操作”中删除当前标注项目时，页内弹窗会明确删除边界，并要求完整输入项目名称后才启用删除按钮。该操作只清理协作标注中心托管的图片副本和标注记录，不删除训练平台项目的数据集，也不删除已经导出的 ZIP。由训练平台项目中心同步的项目，如果平台项目仍存在，下次同步时会重新创建空的标注副本并重新导入图片。

工作区结构：

```text
Workspace/annotation-hub/
├─ annotation_hub.sqlite3
├─ projects/
│  └─ 项目编号/images/
└─ exports/
```

备份前建议先关闭协作标注服务，再复制整个 `Workspace/annotation-hub`。不要只复制 SQLite 主文件而遗漏 WAL 文件。项目包适合迁移单个项目，但不能代替完整工作区备份。

## 安全边界

- 服务使用 PBKDF2-SHA256 保存密码，不保存明文密码。
- 登录会话使用 HttpOnly、SameSite Cookie，并限制短时间登录失败次数。
- 图片会复制进工作区，浏览器不能任意读取服务器文件。
- 项目导入包会检查格式、成员路径和单文件大小。
- 共享模式仅面向可信局域网，不要在路由器上做公网端口映射。
- 当前局域网模式使用 HTTP；需要跨公网时应使用 VPN 或带 HTTPS 的反向代理。

## 停止服务

Windows：

```text
关闭协作标注中心.cmd
```

Ubuntu：

```bash
bash ubuntu_stop_annotation.sh
```

停止服务不会删除账号、图片、项目、标注或导出文件。
